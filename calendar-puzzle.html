What do the counters mean?
  • States: recursive search entries, including the root, solutions, and dead ends.
  • Placement attempts: edges traversed; equal to states minus one in a completed run.
  • Dead ends: visited states with a cell or piece requirement that has zero legal candidates. A branch can also have no solutions because all its descendants fail.
  • Forced choices: nonterminal states whose chosen requirement has exactly one candidate.
  • Depth: number of pieces placed, including fixed pieces, at most ten.
  • Subtree totals: exact visited-state and solution counts below a recorded node, including its omitted descendants.

Counters describe the actual deterministic search; they are not estimates of human puzzle difficulty. Normal runs retain counters but no tree. Recorded runs retain every visited state and exact counters for the entire search. Stopping a run leaves an incomplete count from its last progress update; a tree is available only after completion.

compare means, not sums, because groups have different numbers of dates. One year's weekday averages mix different month/day positions; they do not isolate a weekday effect. Solution counts measure the number of valid arrangements, not necessarily how easy a date feels. The year only determines the weekday and whether February 29 is valid.

How the solver works

This is an exact-cover problem. Each possible piece placement is an option covering several board cells and using one piece. Manually placed pieces are applied as fixed constraints before search. A solution must satisfy all 47 cell requirements and all ten piece requirements exactly once.

  1. Generate every distinct rotation and reflection of each piece. Normalize coordinates and remove duplicate orientations.
  2. Generate placements inside the board. Exclude any placement covering one of the three date cells.
  3. Choose the remaining requirement with the fewest legal placements: either an uncovered cell or an unused piece.
  4. Try each candidate placement. Remove its satisfied requirements and conflicting placements, recurse, then restore them.
  5. A requirement with no candidates is a dead end. If every requirement is satisfied, record the solution. Continue searching to get the exact count.
search(remaining requirements):
    count one visited state
    if no requirements remain:
        record current placement list
        return

    q = requirement with fewest available placements
    if q has zero placements:
        record dead end and its reason
        return

    for placement in candidates(q), in fixed order:
        select placement
        remove satisfied requirements and conflicts
        search(remaining requirements)
        restore requirements and conflicts
        deselect placement

The implementation uses Algorithm X with dancing links: linked lists stored in integer arrays let the search remove and restore conflicting options without copying the whole board. Choosing the smallest constraint is a heuristic for speed, not a guess about the final solution. One candidate means a forced move. Ties use a fixed order, not a learned score.

Every valid arrangement must use exactly one candidate for the chosen requirement. Exploring every candidate therefore preserves completeness. Duplicate rotations are removed before search; placement order does not produce duplicate solutions because each state has one deterministically chosen requirement.

Implementation notes

The first step was to turn the photograph into a grid and a set of piece shapes. The board has 50 squares: 12 months, 31 dates, and seven weekdays. The ten pieces cover 47 squares, which leaves exactly three exposed. The shapes in the tray are the ones used by the solver, with both rotation and flipping allowed.

This fits an exact-cover search quite naturally. Every square needs to be covered once, and every piece needs to be used once. At each step, the solver looks for the square or piece with the fewest remaining placements. That often exposes a dead end quickly. It tries every available placement before giving up on a branch, so it can count all solutions rather than just find the first one.

The search uses Algorithm X with dancing links to remove conflicting placements and restore them when it backtracks. Duplicate rotations are removed beforehand, and choices are tried in a fixed order so the results are reproducible. One tempting shortcut would be to reject empty regions whose area is not divisible by five, but that would be wrong here: three of the pieces have four squares. The implemented checks rely on overlaps, board boundaries, and whether each remaining square and piece still has a legal placement.

The search runs in a background worker so you can keep using the page while it counts. If you stop it, the number shown is only a lower bound. The yearly comparison saves completed counts in browser storage; resuming skips those dates. Everything is contained in this HTML file, so it works locally without a server or external libraries.

Hints take successive pieces from one valid solution. Pieces you have already placed stay fixed, and each hint also counts how many of the solutions found so far agree with the resulting board. Moving a piece yourself starts a new problem. Dragging, clicking, rotating, and flipping all use the same placement checks.

The explorer records every visited state in a compact numeric array, using 32 bytes per state plus spare allocation capacity. Each record stores its parent, the piece placement, and the search decision and counts. Boards are reconstructed from the path to a node rather than saved separately. The worker transfers the array to the page without copying it. Child lists are derived when you open a branch, and only the selected few levels are drawn. This keeps the full search available without building hundreds of thousands of screen elements.

To check the results, every arrangement was validated for three dates: 1,294 solutions for September 5, 2026; 4,594 for February 29, 2024; and 2,485 for December 31, 2026. None reused a piece, overlapped, or covered an exposed date square. A separate backtracking implementation also gave 1,294 for September 5. Fixing three pieces from one arrangement left 12 completions, exactly matching the corresponding subset of the full results.

Programmatic checks also covered hints, dragging, selection, date alignment, and tree navigation. They do not replace a visual check in a browser, or confirm the original transcription of the physical pieces. If a shape or the flipping rule differs from your puzzle, its solution counts will differ too.

Help

  • Place: Drag a piece from the tray onto the board, or select it and click a board cell. Clicking positions the piece’s top-left bounding corner. Green means it fits; red means it does not.
  • Select / deselect: Click a piece to select it. Click it again, click outside, or press Escape to deselect it.
  • Move: Drag a placed piece to another position, or select it and use the arrow keys.
  • Rotate / flip: Select a piece, then use Rotate (R) or Flip (F).
  • Return / clear: Return sends the selected piece back to the tray; Clear empties the board. You can also drag a placed piece back to the tray.
  • Undo: Click Undo or press Ctrl/Cmd+Z to reverse the last game action.
  • Solve / hint: Solve completes your current arrangement. Hint reveals one additional piece.
  • Saved progress: Your arrangement and completed date counts are saved automatically in this browser. Reopen the same file to continue.
  • Browse solutions: Use the arrows or solution number beneath the board to view other solutions.
